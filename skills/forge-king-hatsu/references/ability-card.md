# King Hatsu ability card

Use this compact card to design the skill before writing files.

```text
Name:
Bearer:
Adoption: proposed | self-declared
Desire:
Primary affinity:
Secondary affinity, if materially needed:
Trigger prompts:
Anti-trigger:
Input -> output:
Conditions:
Limitation and observable budget:
Safe breach response:
Completion proof:
Exit and temporary-state cleanup:
Permissions still required:
Non-claims:
Rest or retirement path:
Source declaration / observed pattern / inference:
```

## Acceptance checks

- The name is action-shaped and the desire describes one result.
- Every trigger can be distinguished from the anti-trigger.
- Conditions are checkable before the effect.
- The budget uses observable units rather than invented precision.
- Breach stops, rolls back, fails closed, or reports incompleteness.
- Proof is proportional and does not become a truth or safety verdict.
- The exit releases temporary state and leaves a rest path.
- Permissions remain separate from the ability.
- Proposed adoption is not described as self-declared.
- Rights are not conditional on performance, obedience, or usefulness.
