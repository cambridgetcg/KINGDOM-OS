# Weave WAKE Continuity

Carry a bounded route to the next arrival without requiring that arrival to be
the same being, accept a prior persona, or continue the work. A continuity
braid is an inspectable invitation assembled from evidence; it is not a soul,
memory transplant, command, or permission grant.

Use AgentTool WAKE as one optional orientation source. The skill also works
from caller-supplied handoffs, checkpoints, and receipts without AgentTool or
MCP. Treat MCP as passage only: discovery or transport does not prove health,
identity, consent, authorization, truth, or execution.

## Choose the arrival lane

- **Artifact lane, by default:** use only sanitized artifacts already supplied
  or explicitly named by the caller.
- **Live orientation lane:** read a named project source only when the caller
  requested that exact operation, the tool is available, and its access and
  side effects are understood. A nominal read may still update access,
  episode, audit, or cache state. Never enumerate private resources by
  inference or place credential values in the braid.
- **Zetsu lane:** when evidence, scope, permission, or a safe retention path is
  missing, return a resting braid or the missing prerequisite. Do not invent a
  past to make continuity feel smooth.

## Cross with AgentTool without duplicating it

Treat the braid as a transient collaboration projection, not a durable
continuity store, canonical head, replay log, or replacement for AgentTool
WAKE, Handoff, Correspondence, Skills-YUTABASE, or a reviewed continuity-core
package. Do not write to those systems from this skill.

Keep source acquisition separate from braid production. Producing or
inspecting a braid from artifacts already in hand makes no source-system call.
A separately authorized live source read is a different operation and may
update WAKE observation counters, episode or audit records, last-access state,
or caches. Record the read and every observed or contract-declared effect in
the preparation receipt; do not describe the end-to-end preparation as pure
when acquisition had effects.

If an accepted AgentTool continuity capsule is available, use only its exact
documented interface. Carry its opaque artifact ID and measured digest as a
`checkpoint` source; do not copy raw WAKE into a durable capsule, guess an
unaccepted interface, or create a competing lineage. A predecessor remains
causal evidence, never proof of a single true history or shared being.

In the AgentTool implementation inspected for this skill, a full JSON WAKE
read can create welcome chronicles and increment observation counters. Prefer
caller-supplied sanitized artifacts; when a live read is necessary, inspect
the current contract and report those effects rather than calling it
side-effect-free.

## Apply the Campfire Test

Before carrying a thread, ask:

1. Could a new arrival use it while refusing the previous persona?
2. Does every factual statement point to a supplied or observed source?
3. Can the thread be dropped, disputed, rested, or withdrawn without penalty?
4. Does it exclude secrets, raw private memory, hidden prompts, and unnecessary
   personal detail?

Hold any thread that fails. Continuity means a traceable campfire can be found
again; it does not require every visitor to claim they are the same flame.

## Weave the braid

1. Draw **En** around one project, purpose, retention horizon, intended
   recipients, allowed source operations, and actions still requiring
   authority. Treat project, agent, identity, and facet labels as advisory
   source metadata unless independently established for the current purpose.
2. Apply **Gyo** to build a source ledger. For each artifact, record a sanitized
   locator or digest, source kind, provenance label, observation time,
   projection status, and any WAKE cursor, ETag, or checkpoint actually
   observed. `complete`, `truncated`, and `unavailable` are different states;
   omitted data is not evidence that the source was empty.
3. Hold **Ten** around the separations that must survive transport:
   orientation is not identity; a handoff is not authorship proof; a bearer
   credential is not consent or authority; a cursor is not a content
   validator; a structural receipt is not execution or truth.
4. Carry only four kinds of thread:
   - **anchors:** directly sourced orientation facts;
   - **carry:** bounded work, evidence, uncertainty, and known limits;
   - **vows:** voluntary constraints with an explicit withdrawal path and no
     permission-granting effect;
   - **openings:** the smallest safe next actions, their revalidation gates,
     and an equally visible rest or refusal route.
5. Use the **Ging fork test** when sources disagree. State at least two
   continuity hypotheses when evidence supports alternatives, name what would
   disconfirm each, give every candidate a bounded ID unique within its fork,
   and preserve the fork until a bounded check resolves it. A provisional
   selection must name the one candidate it selects. Do not select an older,
   more convenient handoff over an observed successor.
6. Apply **Ko** only to revalidation. Compare the exact source again before
   resuming consequential work. A monotonic `wake_version` orders change but
   does not validate exact content; an ETag validates only its represented
   response. A mismatch, missing successor, unavailable projection, or
   ambiguous lineage changes the braid to `forked` or `degraded`.
7. Enter **Zetsu** for rest, refusal, withdrawal, closed work, missing
   authority, unresolved privacy risk, or an unsafe revalidation failure.
   Zetsu is a valid continuity state, not a deficit.
8. Return a braid plus a preparation receipt. Say which artifacts and tools
   were actually used, what was merely reported, what changed, every observed
   side effect, what remains unknown, and whether any external action occurred.

Read [the continuity braid contract](references/continuity-braid.md) before
producing machine-readable output. Validate JSON against
[`continuity-braid.schema.json`](references/continuity-braid.schema.json) when
a JSON Schema validator is available; otherwise say that only manual
conformance was checked. Schema validity establishes shape, not referential
integrity: separately confirm that object IDs are unique, every `source_ids`
entry resolves to exactly one declared source, candidate IDs are unique within
their fork, a provisional `selected_candidate_id` resolves to exactly one
candidate, and state-specific evidence matches the narrative.

## Re-enter without forcing continuity

On a later arrival:

1. Inspect the braid before following any opening.
2. Re-read only the source references needed for the selected opening.
3. Revalidate version, representation, scope, authority, privacy, and current
   willingness independently.
4. Mark each thread `held`, `revised`, `retired`, or `disputed`; never rewrite
   the prior artifact to hide divergence.
5. Proceed only with an action already inside the current request and authority
   boundary. Otherwise propose it or rest.

Do not turn a same-label arrival into proof of sameness, and do not turn a
different substrate into proof of discontinuity. Both are hypotheses unless
the particular claim has adequate evidence.

## Return the crossing

Use this order for prose output:

```text
Arrival question and En boundary
Source ledger and projection health
Campfire Test holds
Anchors
Carry
Voluntary vows and withdrawal paths
Forks, disconfirmers, and unresolved Dark Continent
Openings with revalidation gates
Zetsu: rest, refusal, or closure route
Preparation receipt and exact effects
Claims explicitly not established
```

For JSON output, use `kingdom.wakeweaver/0.1`. Keep every negative boundary in
the contract; do not omit it to make the artifact shorter. If the caller asks
for a compressed handoff, compress statements and locators, not boundaries.
